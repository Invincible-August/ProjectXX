# 功法系统设计

| 项 | 内容 |
| --- | --- |
| **针对** | 功法双角色（主功法 / 技法）、学习条件、灵根、装备栏展示 |
| **设计日期** | 2026-08-18 |
| **版本** | v0.2.2（口子：展示 + 装备接口；工坊成品单一属性芯片；学习条件/技能引擎未开） |
| **依据** | [`ATTR战斗属性占位设计.md`](./ATTR战斗属性占位设计.md)；体质双效果（本源/旁支）；[`后续待完成.md`](./后续待完成.md) **M3-D03** / **M8-D03** |
| **原则** | 每本功法同时具备主功法与技法两套效果（同体质）；主功法只能装备一本，技法多本；完整施放链仍挂 **M3-D03** |

## 0. 本版开口到哪

已落地：

- 角色页功法栏改为体质同款方格：1 格主功法 + N 格技法。
- `GET /techniques/me` 含已学列表与装备槽；`POST /techniques/equip|unequip` 写槽。
- 悬停功法看说明（名称 / 来源 / `lv.?/lv.?` / 属性小框）；选择栏紧凑方格。装备属性走同一 format。玩家与 NPC 领域对象带灵根；角色面板展示灵根中文名。创角默认杂灵根（轮回新生仍可重选）。

明确不做（本版）：

- 学习条件真实校验（属性阈值 / 灵根 / 修为）。
- 主功法改挂机速率、属性加算按「仅已装备」重算（现行仍按已学等级占位加算）。
- 技法决定可释放技能接入战斗引擎。
- 溺水等战斗公式、功法主动/被动完整链（**M3-D03** / **M8-D03**）。

## 1. 双角色（与体质同构）

每本功法 **同时** 有两套效果，装备时选一个角色，不能同一本同时占主功法与技法。

| 角色 | 槽 | 效果（后续实现） |
| --- | --- | --- |
| 主功法 | 固定 1 格 | 加快修炼速度、提升属性、学会技能 |
| 技法 | 随修为境界增加 | 决定可释放哪些技能 |

修为越高，技法槽越多（`techniques.yaml` `loadout.art_slots_by_major`）。降境不在本版处理。

---

## 2. 学习条件（配置口子，本版不执行）

学会后才能装备。条件可组合（且）：

| 条件 | 机读 | 例 |
| --- | --- | --- |
| 属性到达 | `learn_requires.attrs` | `{ comprehension: 20, strength: 10 }` |
| 灵根是什么 | `learn_requires.spirit_roots` | `[metal_root, thunder_root]`（满足其一即可，除非 `spirit_roots_mode: all`） |
| 修为是什么 | `learn_requires.major_realm` + 可选 `realm_stage` | `qi_refining` / `3` |

未配条件 = 无门槛。本版创角仍发放样本功法，不走本表。

---

## 3. 灵根

- 玩家：`characters.spirit_root_tags_json`（已有）；面板展示中文。创角默认 `mixed_root`。
- NPC：`NpcCharacter.spirit_root_tags`（模板行 `spirit_root_tags`）；与玩家同属 `PlayerNpcCharacter`。
- 灵根目录仍用 `reincarnation.yaml` `spirit_roots`（金木水火土雷 + 杂灵根）。功法 `elements` 对齐：`metal/wood/water/fire/earth/wind/thunder`。
- 心魔抗 / 天劫抗在角色面板进 **根基**（schema 仍属生活键），不是灵根。

## 4. 来源（五种）

玩家可见只这五种。机读英文，展示中文。

| 机读 | 中文 |
| --- | --- |
| `system` | 系统 |
| `sect` | 宗门 |
| `mentor` | 师承 |
| `research` | 自研 |
| `chance` | 机缘 |

**师承**：师傅教给你的，在你这边 **一律显示师承**，不论师傅自己是系统、宗门还是自研拿到的。

旧文案「官方样本」→ 系统。自研定稿写入 `research`。

## 5. 悬停说明（固定格式）

功法、神通、体质、装备共用同一套悬停卡片。输入是「名称 + 角标 + 可选等级 + 属性数组 + 说明」，由 `itemHoverFormat` 从装备 `stats_preview` / 体质效果表 / 功法字段 format 后输出，禁止各栏自己拼一段纯文本。

工坊成品走同一卡片外壳，但属性是 **单一芯片**（见 §5.1），不要把材料/体力拼成一串字符。

框内布局：

```text
┌ 名称                          角标 ┐
│ lv.3/lv.10   ← 仅功法              │
│  [金] [木]   ← 仅功法/神通         │
│  物理攻击              +12         │
│  本源 生命             +20         │
└ 说明（可选）                       ┘
```

| 行 | 规则 |
| --- | --- |
| 名称 | 左上，完整中文名 |
| 角标 | 右上：功法/神通=来源；装备=部位；体质=品阶 |
| 等级 | 仅功法 `lv.{当前}/lv.{上限}` |
| 属性小框 | 金木水火土风雷；无则省略 |
| 属性行 | 从装备 `stats` / 体质 `main_effects`+`sub_effects` format：`中文名` + 已带符号的值（`+12` / `×1.1`） |
| 说明 | 功法 `help_zh`；神通优先 `effect_zh`；空部位写「此部位尚未穿戴」 |
| 技能 | **不**写进功法悬停（技能另条） |

浮层深色底、浅色字（挂到 `body`）。前端实现：`ItemHoverTip.vue` + `utils/itemHoverFormat.ts`。神通/体质在本周期与功法一起落地，不另开迭代。

点槽后的选择栏用 **紧凑方格**（与已装备格同尺寸折行），悬停看上表，再点格装备/卸下；禁止一条候选占满一整行。

### 5.1 工坊成品悬停

炼丹 / 炼器 / 符箓 / 傀儡共用（阵法不进工坊）。数据来自物品 `inspect`（`GET /craft/recipes[].inspect`）。属性只有 **一种**（金木水火土风雷暗），用意是同属性灵根后续可额外收益，本版只展示不结算。无抗性。使用条件只有境界门槛。

```text
┌ 小体力丹                    炼丹等级 0 ┐
│  [木]                                      │
│  功效  [恢复体力]                           │
│  使用条件              境界 无             │
│  ── 说明 ────────────────────────── │
│  详细说明                                  │
└────────────────────────────────────┘
```

右上角标为对应分支制作等级。材料、灵石、体力不写进悬停：点选图纸后「所需材料」含材料与灵石，「所需体力」另栏。

## 6. 技能展示

已装备功法按角色取出 `skills.as_main` 或 `skills.as_art`。有则在方格下方列出技能名；鼠标悬停显示 `effect_zh`。全部为空则整块不渲染。

本版技能只是 YAML 占位文案，不进引擎。

---

## 7. API（本版）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/techniques/me` | `items`（已学）+ `loadout`（槽、技能汇总） |
| POST | `/techniques/equip` | `{ technique_id, slot_type: main\|art, slot_index }` |
| POST | `/techniques/unequip` | `{ slot_type, slot_index }` |

同一本不能占两格；装入已占格则替换。技法 `slot_index` 必须 `< art_slot_cap`。
